## 1. 目的

macOSおよびWindowsでMuziaを起動できる、今後の機能追加の基盤となるアプリシェルを整備する。

Flutterの初期サンプル画面をMuziaの基本レイアウトへ置き換え、起動時の状態をユーザーが確認できるようにする。

## 2. 対象範囲

### 対象

- macOSおよびWindowsでアプリを起動できること
- アプリ名をMuziaとして表示すること
- 基本レイアウトを表示すること
  - サイドバー
  - ツールバー
  - メインコンテンツ領域
  - プレイヤー領域
- 起動直後のライブラリ読み込み状態を表示できること
- 起動状態として、少なくとも読み込み中・空状態・エラー状態を表現できること
- View、ViewModel、状態の責務を分離した構成にすること

### 対象外

- 音楽フォルダの選択・登録
- 音楽ファイルの検出・メタデータ解析
- ライブラリ情報の永続化
- 楽曲一覧、アーティスト一覧、アルバム一覧の実データ表示
- 楽曲の再生・一時停止
- 検索、メタデータ編集、ライブラリからの削除

## 3. 要件

### 機能要件

- REQ-001: macOSでアプリを起動できる。
- REQ-002: Windowsでアプリを起動できる。
- REQ-003: ウィンドウ内にMuziaの基本レイアウトを表示する。
- REQ-004: 起動時にライブラリの読み込み状態を表示する。
- REQ-005: ライブラリがまだ存在しない場合、空状態を表示する。
- REQ-006: 起動処理または初期化処理に失敗した場合、エラー状態を表示する。
- REQ-007: 起動状態の管理をWidgetに直接実装せず、ViewModelまたは同等の状態管理層に分離する。
- REQ-008: 現時点で未実装の操作を、実装済みであるかのように表示しない。

### 非機能要件

- NFR-001: 起動直後に画面が固まらず、処理中であることが分かる表示を行う。
- NFR-002: macOSとWindowsで共通のDartコードを基本とし、プラットフォーム固有処理をこの機能へ持ち込まない。
- NFR-003: 起動状態をWidgetテストで検証できる構造にする。

## 4. 状態

起動状態は、少なくとも以下を扱う。

- `loading`: ライブラリの読み込み中
- `empty`: 利用可能なライブラリ情報がない
- `error`: 初期化または読み込みに失敗

ライブラリの実データ取得は後続の機能で実装する。本機能では、後続処理を差し替え可能な境界を用意し、初期状態を正しく表示できることを優先する。

## 5. 画面仕様

```text
┌─────────────────────────────────────────────┐
│ ツールバー: Muzia / 画面タイトル             │
├──────────────┬──────────────────────────────┤
│ サイドバー    │ メインコンテンツ               │
│              │ 起動状態・空状態・エラー状態    │
├──────────────┴──────────────────────────────┤
│ プレイヤー領域（未選択状態）                  │
└─────────────────────────────────────────────┘
```

- 未実装の操作ボタンは表示しないか、利用できない状態を明確にする。
- 空状態とエラー状態には、ユーザーが状況を理解できる日本語メッセージを表示する。
- ウィンドウサイズの変更に追従し、主要な領域が極端に崩れないようにする。

## 7. 設計メモ

- アーキテクチャの`lib/app/`をアプリ共通のエントリポイントとし、画面固有の処理は`lib/features/`配下に配置する。
- 状態管理ライブラリは未決定のため、本機能では既存依存を増やさず、差し替え可能な最小構成とする。
- ライブラリ読み込みの実装は、後続のフォルダ登録・ファイル検出・永続化機能で追加する。
- 本機能ではユーザーの音楽ファイルへアクセスしたり、変更したりしない。
