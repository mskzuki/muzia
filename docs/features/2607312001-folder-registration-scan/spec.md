# 音楽フォルダ登録・初回スキャン 仕様書

## 文書情報

- 仕様ID: 2607312001
- 対応する全体要件: FR-002、FR-003、FR-004、FR-005
- ステータス: Completed
- 作成日: 2026-07-31

## 1. 目的

ユーザーがローカルの音楽フォルダを登録し、対応する音楽ファイルを初回スキャンして、楽曲一覧として確認できるようにする。

## 2. 対象範囲

### 対象

- フォルダ選択、パス検証、登録・変更
- 登録フォルダ内の対応ファイルの非同期スキャン
- ファイルからのタイトル、アーティスト、アルバム、リリース情報の読み取り
- スキャン結果のライブラリ一覧表示
- 読み込み中、空、エラー状態の表示

### 対象外

- 再スキャン時の差分更新
- 検索、再生、メタデータ編集、ライブラリからの削除
- 元ファイルへのメタデータ書き戻し
- アルバムアートの取得

## 3. 要件

### 機能要件

- [ ] REQ-001: ユーザー操作でフォルダ選択ダイアログを開ける。
- [ ] REQ-002: 存在しないパス、ファイルのパス、重複パスを登録せずエラーを表示する。
- [ ] REQ-003: 登録フォルダを別のフォルダへ変更できる。
- [ ] REQ-004: 対応形式のファイルだけを検出し、音楽ファイル以外を一覧へ追加しない。
- [ ] REQ-005: スキャン中もUI操作を受け付け、進行中であることを表示する。
- [ ] REQ-006: 検出したファイルのメタデータを一覧に表示する。
- [ ] REQ-007: メタデータ欠落時は空欄または代替表示にする。
- [ ] REQ-008: 空フォルダ、アクセスエラー、解析エラーを区別して表示する。
- [ ] REQ-009: スキャンで音楽ファイルを移動・削除・上書きしない。

### 非機能要件

- [ ] NFR-001: ファイル列挙と解析をService/Repositoryに隔離する。
- [ ] NFR-002: macOSとWindowsのパスを`path`で扱い、UIスレッドを長時間ブロックしない。
- [ ] NFR-003: FileScannerServiceとMetadataServiceをFakeへ差し替えてテストできる。

## 4. 完了条件

- [ ] フォルダ登録・変更と初回スキャンが動作する。
- [ ] 楽曲一覧に最低限のメタデータが表示される。
- [ ] 単体、Widget、必要なIntegration Testが追加され成功する。
- [ ] `flutter analyze` と `flutter test` が成功する。

## 5. 設計メモ

`FilePickerService`、`FileScannerService`、`MetadataService`、`MusicRepository`を用い、Viewからファイルシステムへ直接アクセスしない。初回登録時は`docs/database.md`の`tracks`、`track_metadata`、`track_source_metadata`へ保存する。対応形式は採用ライブラリで検証できた形式に限定し、未検証形式を実装済みと扱わない。

## 7. 実装上の補足

フォルダ選択、パス検証、非同期スキャン、メタデータ解析はServiceとして分離し、Repositoryを差し替え可能にした。現在のデフォルトRepositoryは初回スキャンの動作確認用インメモリ実装であり、アプリ再起動後も保持するDrift実装は`library-persistence`スペックで追加する。
