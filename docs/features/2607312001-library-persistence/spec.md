# ライブラリ永続化 仕様書

## 文書情報

- 仕様ID: 2607312005
- 対応する全体要件: FR-010
- ステータス: Draft
- 作成日: 2026-07-31

## 1. 目的

登録フォルダ、検出楽曲、アプリ上のメタデータ、ライブラリからの削除状態をアプリ再起動後も保持する。

## 2. 対象範囲

### 対象

- SQLite/Driftによるライブラリ情報の保存と読み込み
- 起動時の非同期読み込み状態
- 登録フォルダ、楽曲、現在メタデータ、削除状態の保持
- DBアクセスエラーの表示
- スキーママイグレーションの基盤

### 対象外

- DBファイルのバックアップ・復元
- 複数ライブラリ切り替え
- クラウド同期

## 3. 要件

### 機能要件

- [ ] REQ-001: アプリ終了後も登録フォルダを保持する。
- [ ] REQ-002: 検出済み楽曲とメタデータを保持する。
- [ ] REQ-003: アプリ上で編集したメタデータを保持する。
- [ ] REQ-004: ライブラリから削除した状態を保持する。
- [ ] REQ-005: 起動時に保存情報を読み込み、loading/empty/success/errorを表示する。
- [ ] REQ-006: DB破損・読み書きエラーを握りつぶさず表示する。

### 非機能要件

- [ ] NFR-001: View/ViewModelからDBへ直接アクセスしない。
- [ ] NFR-002: RepositoryをインメモリDBへ差し替えてテストできる。
- [ ] NFR-003: ユーザー固有のパスやDB内容を不要にログ出力しない。

## 4. 完了条件

- [ ] 起動時に保存済み状態を復元できる。
- [ ] 登録フォルダ、編集値、削除状態の再起動テストが成功する。
- [ ] Repositoryとマイグレーションのテストが成功する。
- [ ] `flutter analyze` と `flutter test` が成功する。

## 5. 設計メモ

Drift + SQLiteを使用し、テーブルと責務は`docs/database.md`を正とする。書き込みはRepositoryのトランザクションを通じて行い、元の音楽ファイルはDB永続化処理から変更しない。
