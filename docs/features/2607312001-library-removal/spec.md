# ライブラリからの楽曲削除 仕様書

## 文書情報

- 仕様ID: 2607312007
- 対応する全体要件: FR-013、FR-014
- ステータス: Completed
- 作成日: 2026-07-31

## 1. 目的

不要な楽曲をアプリのライブラリから除外しつつ、ユーザーの元の音楽ファイルを安全に残す。

## 2. 対象範囲

### 対象

- 楽曲の単一・複数選択
- 削除対象と対象数の確認ダイアログ
- ライブラリ上の削除状態の保存
- 一覧、検索、アーティスト、アルバムからの除外
- 削除処理のエラー表示

### 対象外

- 元ファイルの削除・移動・変更
- 削除済み楽曲の復元UI
- ゴミ箱連携

## 3. 要件

### 機能要件

- [x] REQ-001: 削除対象を選択できる。
- [x] REQ-002: 実行前に対象楽曲と件数、元ファイルを削除しないことを表示する。
- [x] REQ-003: 確認後、対象をライブラリから除外する。
- [x] REQ-004: 一覧、検索、アーティスト、アルバムへ除外を反映する。
- [x] REQ-005: 元の音楽ファイルを削除、移動、上書きしない。
- [x] REQ-006: 保存失敗時はライブラリ状態を不整合にせずエラーを表示する。

### 非機能要件

- [x] NFR-001: `tracks.removed_at`を用い、物理削除を行わない。
- [x] NFR-002: 複数削除をトランザクションで実行する。
- [x] NFR-003: 削除前後のファイル状態をテストで比較できる。

## 4. 完了条件

- [x] 確認付きで単一・複数削除が動作する。
- [x] 4つの表示経路から削除済み楽曲が除外される。
- [x] 元ファイルが残ることを確認するテストが成功する。
- [x] `flutter analyze` と `flutter test`、必要なIntegration Testが成功する。

## 5. 設計メモ

DBから物理削除せず、`tracks.removed_at`を設定する。`track_metadata`と`track_source_metadata`は保持する。Repository以外からファイル削除APIを呼び出さない。
