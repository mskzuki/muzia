# デザインハンドオフとの乖離是正

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md), [docs/design_handoff/DESIGN_TOKENS.md](../../design_handoff/DESIGN_TOKENS.md), `docs/design_handoff/screenshots/`

## 事象

`docs/design_handoff/` に保存されたデザインハンドオフ（muzy v1.0 UI）と、現在の実装
（`lib/features/app_shell/presentation/app_shell_page.dart` ほか）の見た目が大きく乖離している。
現在の実装はMaterial 3のデフォルトウィジェット（`AppBar` / `ListTile` / `Checkbox`）を
ほぼ素のまま使っており、ハンドオフが定義するトークン・レイアウト・コンポーネント状態を
反映していない。

## 原因

- デザイントークン層が存在しない。テーマは `ColorScheme.fromSeed(seedColor: Colors.indigo)`
  のみで、Radix Indigo/Gray のセマンティックカラー、4pxスペーシング、角丸、タイポグラフィの
  スケールが定義されていない（`lib/shared/theme/` は空ディレクトリ）。
- 各画面がデザイン確定前に実装されており、ハンドオフのコンポーネント仕様
  （テーブル行、選択状態、選択バー、プレイヤーバー等）を参照していない。

## 実装に先立つ確認事項（矛盾・前提）

AGENTS.mdの規定に従い、独断で判断せず以下を報告する。

1. **対象プラットフォームの矛盾**: ハンドオフは「SwiftUI on macOSでネイティブ再現する」
   前提で書かれているが、本プロジェクトはFlutter（macOS / Windows対応）である。
   → 本課題では「SwiftUIの指示はFlutterウィジェットでの再現に読み替える」方針とする。
   トークン（色・字詰め・余白・角丸）とレイアウト構造はそのまま採用し、
   `NavigationSplitView`等の指示は同等のFlutter実装で代替する。
2. **MVP範囲外の画面**: ハンドオフにはプレイリスト、ジャンル、お気に入り(♥)、
   重複レビュー、環境設定、Music.appインポート等が含まれるが、これらは
   `docs/requirements.md` §7でMVP後とされている。本課題ではMVP範囲の画面のみを
   デザインに適合させ、範囲外の画面・列・ボタンは実装しない。
3. **Quality列のデータ不足**: デザインの品質表示（FLAC 96/24、Hi-Resピル、階層色）に
   必要なフォーマット・サンプルレート・ビット深度を、現在の`Track`/DBスキーマは
   保持していない（`fileExtension`のみ）。カバーアート(`artworkHash`)も同様。
   → 本課題ではQuality列とサムネイルは対象外とし、メタデータ拡張は別課題とする。
4. **表示言語**: モックの一覧・サイドバーは英語（Songs, Albums…）だが、
   ダイアログ・メニューは日本語。現在の実装は全て日本語。本課題では現状の日本語を
   維持し、レイアウト・スタイルのみ適合させる。

## 要件

1. `lib/shared/theme/` にデザイントークン層を実装する。
   - `DESIGN_TOKENS.md` §1〜§5 の色（accent / fg / surface / quality / destructive）、
     スペーシング、角丸、タイプスケールを定義する。
   - `ThemeData`（ライト）とセマンティック拡張（`ThemeExtension`）として提供し、
     Widgetから生hexを参照しない。ダークは同じRadixステップのダーク値で定義する。
2. アプリシェルをレイアウト骨格（README「Layout skeleton」）に合わせる。
   - ツールバー: 52px、コンテンツタイトル+曲数表示、右端に検索フィールド。
   - サイドバー: 224px、`sidebarBg`、「ライブラリ」セクション見出し（11px/大文字相当の
     キャプションスタイル）、アイコン+項目名+件数、選択項目はaccent塗り+白文字。
   - プレイヤーバー: 74px、`sidebarBg`、左=曲情報、中央=前/再生/次+シークバー、
     右=音量（transport機能の追加が再生基盤の対応を要する場合、UI枠のみ先行し
     機能は別課題に切り出す）。
3. 楽曲一覧をテーブル形式にする。
   - 列: # / タイトル / アーティスト / アルバム / 時間（時間はデータがあれば。なければ列を保留し理由を記録）。
   - 30px行・ゼブラ縞(`rowStripe`)・ホバー(`rowHover`)・固定ヘッダ(11pxキャプション)。
   - 行クリックで選択（accent塗り+白文字）、⌘/⇧クリックで複数選択、ダブルクリックで再生。
   - 2曲以上選択時、一覧上部に選択バー（accent-a3背景、「N 曲を選択中」+一括編集ボタン）。
   - 右クリックで「曲を再生 / 曲を編集… / ライブラリから削除…（赤）」のコンテキストメニュー。
   - 再生中行はタイトルをaccentText色にする（イコライザアニメーションは任意）。
4. 空状態・警告バナーをデザインに合わせる（`08-empty` / `10-missing` 準拠。
   ドロップゾーンの実際のD&D機能はMVP範囲確認のうえ別途）。
5. アーティスト/アルバムブラウザの行スタイル（アバター・メタ表示・ソフト選択）を
   `03-artists` に寄せる。
6. ダイアログ類（曲編集・一括編集・削除確認）はレイアウト構造が既にデザインに近いため、
   トークン適用（角丸12、ボタンスタイル、フィールド枠線）のみ行う。
