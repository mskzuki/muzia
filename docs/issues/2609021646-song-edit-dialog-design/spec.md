# 曲編集ダイアログのデザイン適合（16-song-edit）

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md) §1（Song Edit Dialog）、
  `screenshots/16-song-edit.png`、`reference_html/screens2.jsx`（`SongDialog`）
- 前提課題: [2609021644-track-metadata-model-extension](../2609021644-track-metadata-model-extension/spec.md)
  （トラック番号・リリース年・ジャンル）

## 事象

現在の曲編集ダイアログ
（[lib/features/library/presentation/metadata_edit_dialog.dart](../../../lib/features/library/presentation/metadata_edit_dialog.dart)
`MetadataEditDialog`）はデザインと以下が異なる。

- フィールド構成: デザインは 曲名（初期フォーカス） / アーティスト / アルバム（2カラム） /
  トラック / リリース年（各96px幅の狭い入力） / ジャンル（テキスト+サジェストチップ）。
  現在は 曲名 / アーティスト / アルバム / リリース情報（自由記述）の縦一列のみ。
- ヘッダ: デザインは小さなカバー+曲・アルバムのアイデンティティ表示。現在はタイトル文字列のみ。
- 幅: デザインは〜470pxの中央モーダル。現在は `AlertDialog` 既定。

## 原因

デザイン確定前のMVP実装（FR-011の最低限項目）のままで、ハンドオフの
フィールド構成・レイアウトが反映されていない。

## 実装に先立つ確認事項

1. **編集項目の拡張**: トラック番号・リリース年・ジャンルの編集はFR-011の列挙に
   含まれない（「最低限」のため矛盾はしない）。要件更新の要否は前提課題の
   確認事項1と合わせて確認する。
2. **カバー表示**: アートワークはMVP後のため、ヘッダのカバーは既存のプレースホルダ
   グリフ（音符アイコン）で代替する。
3. **Undo/Redo（⌘Z/⌘⇧Z）**: ハンドオフは編集のUndo/Redoを求めるが、編集履歴基盤が
   未実装のため本課題の対象外とし、必要なら別課題とする。

## 要件

1. フィールド構成をデザインに合わせる:
   曲名（初期フォーカス） / アーティスト・アルバム（2カラム） /
   トラック・リリース年（狭い数値入力、2カラム） / ジャンル（テキスト入力+
   既存ジャンルのサジェストチップ）。
2. トラック番号は正の整数、リリース年は4桁数値のバリデーションを行う。
   空欄は未設定（null）として保存する。
3. ヘッダにプレースホルダカバー+曲名・アルバム名を表示する。
4. ダイアログ幅〜470px・角丸・ボタン様式を `16-song-edit.png` に合わせる
   （一括編集ダイアログと同じ様式ファミリー）。
5. フッターは「キャンセル / 保存」。曲名必須の既存バリデーションは維持する。

## 完了条件

- `16-song-edit.png` と実機表示を並べ、フィールド構成・レイアウトが一致する
  （カバーはプレースホルダで許容）。
- 新フィールドの保存・表示反映がWidgetテストで検証されている。
- `flutter analyze` / `flutter test` が通り、メタデータ編集のIntegration Testが
  維持または更新されている。
- 確認事項1〜3の判断が作業報告に記載されている。
