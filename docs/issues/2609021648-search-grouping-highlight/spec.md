# 検索のグループ化・ハイライト・⌘Fフォーカス（14-search）

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md)
  「Interactions & Behavior — Search」、`screenshots/14-search.png`

## 事象

デザインの検索仕様と現在の実装
（[lib/features/library/domain/library_search.dart](../../../lib/features/library/domain/library_search.dart)、
[lib/features/app_shell/presentation/app_shell_page.dart](../../../lib/features/app_shell/presentation/app_shell_page.dart)）
の差分:

- **結果のグループ化**: デザインは「アルバム」「楽曲」等の見出し付きグループで表示。
  現在は楽曲一覧の単純フィルタのみ。
- **一致箇所のハイライト**: デザインは一致した部分文字列にgold-a4背景。現在はなし。
- **⌘F**: デザインは⌘Fでツールバー検索フィールドにフォーカス。現在は未実装。
- **マッチ方式**: デザインは「incremental, prefix-based, diacritic/case-insensitive」。
  現在の `LibrarySearch` のマッチ方式（部分一致等）との差を確認し、揃える。

FR-008（検索対象: タイトル/アーティスト/アルバム、0件時の明示）は満たしている。

## 原因

MVPの検索はFR-008の最低限（キーワードフィルタ）として実装され、
ハンドオフの提示形式（グループ化・ハイライト）が反映されていない。

## 実装に先立つ確認事項

1. **グループの単位**: デザインの例は「Albums / Songs」等。本課題では
   「アルバム / アーティスト / 楽曲」の3グループとし、各グループ内は
   一致度順（前方一致優先）とする方針で良いか確認する。
2. **グループ行の遷移先**: アルバム/アーティストのグループ項目を選択した際の挙動
   （アーティスト・アルバムブラウザの該当箇所へ遷移）が実装可能か確認し、
   困難な場合は該当グループの表示のみ（選択不可）とするか判断する。
3. **prefix-based**: 完全な前方一致のみだと途中一致が拾えなくなる。
   「単語の前方一致を優先しつつ部分一致も許容」とする場合は要件（FR-008）と
   矛盾しないが、デザイン文言との差として作業報告に記載する。

## 要件

1. ⌘F（Windowsでは Ctrl+F）で検索フィールドにフォーカスする。
2. 検索はインクリメンタル（入力ごとに更新）で、大文字小文字・ダイアクリティカル
   マークの差を無視する。
3. 検索結果をグループ見出し付きで表示する（確認事項1の方針に従う）。
4. 一致した部分文字列をgold系トークン（`DESIGN_TOKENS.md` のgold-a4相当）の
   背景でハイライトする。
5. 0件時の空状態表示（既存）は維持する。
6. 検索ロジック（正規化・マッチ・グルーピング）は単体テスト可能な形で
   `library_search.dart` 側に置く。

## 完了条件

- `14-search.png` と実機表示を並べ、グループ見出し・ハイライトの表現が一致する。
- 正規化（大文字小文字・ダイアクリティカル）・グルーピング・ハイライト範囲の
  単体テストがある。
- ⌘FフォーカスのWidgetテストがある。
- `flutter analyze` / `flutter test` が通り、検索のIntegration Testが維持または
  更新されている。
- 確認事項1〜3の判断が作業報告に記載されている。
