# 欠損ファイルバナーのアクションと該当行の表示（10-missing）

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md) §10、
  `screenshots/10-missing.png`、
  [docs/issues/2607312329-scan-failure-track-state](../2607312329-scan-failure-track-state/)

## 事象

現在の警告バナー
（[lib/features/app_shell/presentation/app_shell_page.dart](../../../lib/features/app_shell/presentation/app_shell_page.dart)
`_WarningNotice`）はamber様式のみ適合しており、デザイン `10-missing` と以下が異なる。

- **アクション**: デザインはバナー右に「Locate… / Remove」アクションと閉じる✕。
  現在はテキストのみで、閉じることも対処することもできない
  （是正課題 2608222333 で「ViewModelに解除APIがないため見送り」とされた積み残し）。
- **該当行の表示**: デザインは利用不可の楽曲行を淡色化（テキスト→tertiary）し、
  Quality欄にamberの「Unavailable」フラグ、時間に「—」を表示する。現在は
  行単位の表現がなく、どの曲が利用不可か一覧から判別できない。

FR-009は「ファイルが移動・削除されていて再生できない場合は、原因が分かるエラーを
表示する」ことを求めており、行単位の可視化はこれを補強する。

## 原因

警告はスキャン時のメッセージ集計として実装されており、「利用不可のトラック」という
行単位の状態がViewModel/ドメインに存在しない。バナー解除のAPIもない。

## 実装に先立つ確認事項

1. **「Locate…」(場所を再指定して再リンク)** は、ファイルハッシュによる再同定を
   前提とする機能でMVP範囲を超える。本課題では対象外とし、バナーのアクションは
   「削除…（該当曲をライブラリから削除、既存の確認ダイアログを流用）」と
   閉じる✕のみとする方針で良いか確認する。
2. **利用不可の判定タイミング**: スキャン時の検出に加え、再生失敗時にも該当曲を
   利用不可としてマークするかを確認する（最小実装はスキャン時のみ）。

## 要件

1. トラックに「利用不可」状態を導入し、スキャン時にファイルが見つからない楽曲を
   利用不可としてマークする（ファイルが再度見つかれば解除する）。
2. 利用不可の楽曲が1曲以上ある場合、ツールバー直下にamberバナーを表示する:
   警告アイコン+「N曲が利用できません。」+説明+「削除…」アクション+閉じる✕。
   - 閉じる✕はバナーを非表示にする（次回の状態変化で再表示して良い）。
   - 「削除…」は利用不可の楽曲を対象に既存の削除確認フローを開く。
3. 一覧の該当行を淡色化（テキストをtertiary相当）し、時間列（存在する場合）に
   「—」、行内にamberの「利用不可」表示を置く。利用不可の行はダブルクリックでの
   再生を試みず、理由を表示する。
4. 既存のスキャン失敗警告（`warningMessage`）との表示関係を整理し、両方が
   同時に出る場合の優先順位を決めて作業報告に記載する。

## 完了条件

- `10-missing.png` と実機表示を並べ、バナー構成・該当行の淡色表示が一致する
  （「Locate…」の不在は確認事項1の判断として許容）。
- 利用不可状態の検出・解除・削除フローがテストで検証されている。
- `flutter analyze` / `flutter test` が通る。
- 確認事項1〜2と要件4の判断が作業報告に記載されている。
