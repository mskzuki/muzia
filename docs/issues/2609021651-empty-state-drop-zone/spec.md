# 空状態のドラッグ&ドロップゾーン（08-empty）

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md) §8
  「Interactions & Behavior — Drag & drop」、`screenshots/08-empty.png`

## 事象

空状態（グリフ+見出し+説明+「フォルダを登録」ボタン）は適合済みだが、デザインの
**ドラッグ&ドロップゾーン**（420×132、破線枠。ドラッグ中のアクティブ状態は
accent枠+accent-a2塗り+accent文字）が存在しない。デザインではフォルダをドロップ
するとインポート（フォルダ登録・スキャン）が開始される。

是正課題 2608222333 では「MVP範囲外の機能追加になるため見送り」とされたが、
D&Dは既存のFR-002（フォルダ登録）の**登録手段の追加**であり、新機能ではなく
デザイン適合の積み残しとして扱う。

なお「Import from Music.app」ボタンはMVP範囲外（外部ライブラリ取り込み）のため
本課題の対象外とする。

## 原因

デスクトップD&D受け入れの実装が未着手のまま、空状態のスタイル適合のみ先行した。

## 実装に先立つ確認事項

1. **FR-002との関係**: D&Dによる登録をFR-002の登録手段として要件に追記するかを
   確認する（追記しない場合もUIとしては実装する）。
2. **ドロップ対象の検証**: フォルダ以外（ファイル・複数項目）がドロップされた場合の
   挙動（フォルダのみ受け付け、単一ファイルは親フォルダ登録にせず拒否メッセージ、等）
   を実装時に決めて作業報告に記載する。
3. **macOSのサンドボックス**: ドロップで得たパスに対して、既存のセキュリティ
   スコープ付きブックマーク（`security_scoped_bookmark_service.dart`）と同じ
   永続アクセス手続きが必要。D&D由来のパスでブックマークを作成できることを
   検証してから本実装に入る。

## 要件

1. 空状態に破線枠のドロップゾーン（約420×132、「ここに音楽フォルダをドロップ」等の
   案内文）を表示する。
2. フォルダのドラッグオーバー中はアクティブ状態（accent枠+accentSoft塗り+
   accent文字）に切り替える。
3. フォルダをドロップすると、既存のフォルダ登録→スキャンと同じフローを実行する
   （ブックマーク作成・エラー処理を含め既存処理を流用する）。
4. フォルダ以外のドロップは受け付けず、理由を表示する（確認事項2の方針に従う）。
5. ライブラリに楽曲がある状態でのウィンドウ全体へのドロップ対応（デザイン
   「or window」）は任意とし、実装しない場合はその旨を記録する。

## 完了条件

- `08-empty.png` と実機表示を並べ、ドロップゾーンの通常/アクティブ状態が一致する
  （「Import from Music.app」の不在はMVP範囲判断として許容）。
- ドロップ→登録→一覧表示がmacOSのIntegration Testまたは手動確認で検証されている
  （D&Dの自動化が困難な場合は手動確認の手順と結果を記録する）。
- `flutter analyze` / `flutter test` が通る。
- 確認事項1〜3の判断が作業報告に記載されている。
