# メタデータ編集のUndo/Redo（⌘Z / ⌘⇧Z）

## 文書情報

- 種別: 既存実装の是正（UIデザイン適合・操作性）
- 作成日: 2026-09-02
- 参照: [docs/design_handoff/README.md](../../design_handoff/README.md)
  「Interactions & Behavior — Song editing」「§14 SwiftUI（one undoable transaction）」
  「State Management — Edits（undo stack）」

## 事象

ハンドオフは、曲編集・一括編集の保存を Undo/Redo（⌘Z / ⌘⇧Z）可能とし、
一括編集は「1回のUndoで戻せる1トランザクション」として適用することを求めている。
現在の実装には編集履歴の仕組みがなく、保存した編集を取り消す手段がない。

## 原因

MVPのメタデータ編集（FR-011 / FR-012）はUndoを要件に含んでおらず、
編集適用が履歴を持たない単発の更新として実装されている。

## 実装に先立つ確認事項

1. **要件との関係**: Undo/RedoはFR-011/FR-012にない拡張。要件へ追記するか、
   デザイン適合の範囲として実装するかを確認する。
2. **対象操作**: 本課題の対象は「曲編集の保存」「一括編集の適用」とする。
   ライブラリからの削除のUndoは影響範囲が広い（DB上の削除状態・一覧再構築）ため
   対象外とし、必要なら別課題とする方針で良いか確認する。
3. **履歴の寿命**: アプリ内のインメモリ履歴とし、再起動後は保持しない
   （永続Undoは行わない）方針で良いか確認する。

## 要件

1. 曲編集の保存・一括編集の適用を、それぞれ1件のUndo可能な操作として
   履歴スタックに積む。一括編集は選択全曲への変更を1操作として扱う。
2. ⌘Z（Ctrl+Z）でUndo、⌘⇧Z（Ctrl+Shift+Z / Ctrl+Y）でRedoできる。
   ダイアログ内のテキスト編集中はテキストフィールド自身のUndoを優先する。
3. Undo/Redoの結果は一覧・検索・アーティスト/アルバムブラウザ・DBに反映する
   （FR-010の永続化と整合させる）。
4. 履歴ロジックはUIから分離し、単体テスト可能にする。

## 完了条件

- 曲編集・一括編集それぞれについて、適用→⌘Z→⌘⇧Z の往復で値と永続化状態が
  正しく戻る/進むことがテストで検証されている。
- `flutter analyze` / `flutter test` が通る。
- 確認事項1〜3の判断が作業報告に記載されている。
