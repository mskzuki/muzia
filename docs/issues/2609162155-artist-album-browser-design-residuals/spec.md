## 事象

課題 2609021652 は「行スタイル・ヒーロー・アルバムカードは適合済み」を前提に
再生導線と楽曲行を対象としているが、2026-09-16 の突合で以下がデザインと異なることを
確認した。実装箇所は `lib/features/library/presentation/artist_album_browser.dart`
および `lib/features/library/domain/library_catalog.dart`。

## 原因

課題 2608222333 のブラウザ画面への適用がトークン適用と行のソフト選択に留まり、
`03` / `05` / `06` の各要素を個別に突き合わせていなかった。また `trackNumber` /
`releaseYear` / `genre` / `durationMs` が当時のモデルに存在しなかった。

## 実装に先立つ確認事項

1. **A3 アーティスト行の内容**: 03スクリーンショット版（サムネ+ジャンル、チェブロンなし）
   と README 版（アバター+アルバム数・曲数+チェブロン）のどちらを正とするか。
   2609021654 の資料側確認と合わせて決める。
2. **A1 ソート表示**: デザインの「Recently Added」はMVPにソート機能がないため、
   名前順固定の表示（またはサブヘッダの件数のみ）に読み替えて良いか。
3. **G1 アルバムカードの選択状態**: 2609021652 は「アルバム選択でその楽曲に絞り込む
   挙動を維持」としている。デザインには選択状態がないため、2px 枠を廃止して
   ソフトな tint（accent-a3）で表現するか、絞り込み自体をアルバム詳細（D1）への
   遷移に置き換えるかを決める。
4. **D1 アルバム詳細の位置づけ**: アルバム選択時の右ペインをアルバム詳細ヒーロー+
   トラックリストに置き換える（アーティストヒーローは非表示）で良いか。

2026-09-16 の暫定判断（質問が中断されたため推奨案で実装。異議があれば修正する）:

- 確認事項1: `03-artists.png` / `app.css .am-row` 版（44px 角丸サムネ + 名前 + ジャンル、
  チェブロンなし）。ジャンル未設定のアーティストは「Nアルバム · N曲」を出す。
- 確認事項2: 件数「N アーティスト」と「名前順」の静的表示。
- 確認事項3: 選択枠は廃止。アルバムカードのクリックでアルバム詳細（D1）へ遷移する。
- 確認事項4: アルバム選択時は右ペイン全体をアルバム詳細（ヒーロー + トラックリスト）に
  置き換える。チェブロンを見送ったため、ヒーロー上に「‹ アーティスト名」の戻る導線を置く。

## 要件

1. A1・A2・H1・G1・G2・D2 を `app.css` の値に合わせる（幅・余白・角丸・影・色）。
2. A3 は確認事項1の決定に従い、行の情報構成を統一する。
3. H2 はアーティスト全体のアルバム数・曲数・代表ジャンル（最多ジャンル、なければ省略）・
   合計時間（`durationMs` の合計、null は除外）を表示し、アルバム選択で変動させない。
4. D1 はアルバム選択時にアルバムヒーロー（プレースホルダカバー、キッカー、タイトル、
   アーティスト、「年 · N曲 · 合計時間」、再生）を表示する。再生は 2609021652 の
   確認事項1と同じ扱い（連続再生未対応時は先頭1曲）。
5. D3 は `LibraryCatalog.tracksFor` にトラック番号順（null は末尾、同順はタイトル順）の
   ソートを追加し、# にトラック番号（null は連番）を表示する。ソートは単体テストで検証する。
6. 2609021652 の楽曲行仕様（28px プレースホルダ・時間・ダブルクリック再生・
   コンテキストメニュー）と競合しないよう、同課題と同一ブランチで進める。
