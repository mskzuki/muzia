## 2. 概要

Muziaは、ユーザーのローカルに保存された音楽ファイルを管理・検索・再生するためのデスクトップアプリケーションである。

音楽ファイルの保存場所を登録すると、ファイルから取得した情報をライブラリとして表示し、ユーザーが楽曲を探しやすく整理できるようにする。

## 3. 目的

- ローカルに散在する音楽ファイルを一元的に管理する
- 楽曲を素早く検索できるようにする
- アルバム、アーティスト、ジャンルなどの情報を見やすく表示する
- デスクトップ環境で快適に音楽を再生できるようにする
- ユーザーの音楽ファイルを安全に扱う

## 4. 対象ユーザー

- 自分のPCに音楽ファイルを保存しているユーザー
- ストリーミングサービスではなく、ローカル音源を管理したいユーザー
- 楽曲数が増えても検索・整理しやすい音楽管理アプリを求めるユーザー

## 5. 対象プラットフォーム

### 対象

- macOSデスクトップ
- Windowsデスクトップ

### 対象外

初期リリースでは、以下を対象外とする。

- Webブラウザ
- iOS / iPadOS
- Android
- クラウドストレージへの自動同期
- 音楽配信サービスとの連携
- 音楽ファイルの違法な取得・共有を支援する機能

## 6. 用語

| 用語 | 定義 |
| --- | --- |
| ライブラリ | アプリが管理する音楽ファイルの一覧 |
| 音楽ファイル | ユーザーのローカルストレージに保存された音声ファイル |
| メタデータ | タイトル、アーティスト、アルバムなどの楽曲情報 |
| 登録フォルダ | ライブラリに含める音楽ファイルを検索するフォルダ |
| プレイリスト | ユーザーが任意の順番でまとめた楽曲の集合 |

## 7. MVPの範囲

### MVPに含める機能

- アプリ起動
- 音楽フォルダの登録、変更
- 登録フォルダ内の音楽ファイルの検出
- 楽曲一覧の表示
- アーティスト一覧の表示
- アーティストごとにアルバムを一覧表示
- タイトル、アーティスト、アルバムによる検索
- 楽曲の選択と再生、一時停止
- ライブラリ情報の永続化
- 基本的なエラー表示
- 楽曲のタイトル、アーティスト、アルバム、リリース情報の変更
- 複数の楽曲を選択し、まとめてメタデータを変更
- 選択した楽曲をライブラリから削除（ファイルは削除しない）

### MVP後に検討する機能

- プレイリストの作成・編集
- お気に入り、評価、タグ付け
- 楽曲名、アルバム名、曲順、リリース情報、アルバムアートの表示・取得
- 再生履歴
- スマートプレイリスト
- 重複ファイルの検出
- メタデータのファイルへの書き戻し
- 複数ライブラリの切り替え
- キーボードショートカットの拡充
- macOS / Windows固有のメディアキー対応
- wavからmp3変換
- ライブラリのバックアップ

## 8. 機能要件

### FR-001 アプリ起動

アプリはmacOSおよびWindowsで起動できなければならない。

起動時に、ライブラリの読み込み状況がユーザーに分かる状態を表示する。

### FR-002 フォルダ登録

ユーザーは、音楽ファイルを含むローカルフォルダを登録・変更できなければならない。

登録時の要件:

- フォルダ選択操作をユーザーが明示的に開始できる
- 登録済みフォルダを重複登録しない
- 登録済みフォルダを別のフォルダへ変更できる
- フォルダが存在しない場合はエラーを表示する
- アプリはユーザーの許可なくフォルダ内のファイルを変更しない

### FR-003 音楽ファイル検出

登録フォルダ内の対応音楽ファイルを検出し、ライブラリに追加できなければならない。

対応するファイル形式は、技術検証後に確定する。

初期候補:

- MP3
- FLAC
- M4A / AAC
- WAV
- Ogg Vorbis

### FR-004 メタデータ表示

検出した楽曲について、ライブラリ上で管理するメタデータを表示する。

最低限、以下の項目を扱う。

- タイトル
- アーティスト
- アルバム
- リリース情報

メタデータが存在しない場合は、空欄または適切な代替表示を行う。

### FR-005 楽曲一覧

ライブラリ内の楽曲を一覧表示できなければならない。

- タイトル、アーティスト、アルバムを確認できる
- 一覧から楽曲を選択できる
- 大量の楽曲を表示する場合でも、操作を継続できる
- 読み込み中、空の状態、エラー状態を表示する

### FR-006 アーティスト一覧

ライブラリ内のアーティストを一覧表示できなければならない。

- アーティスト名を確認できる
- アーティストを選択できる
- 楽曲が存在しないアーティストを表示しない
- 空の状態とエラー状態を表示する

### FR-007 アルバム一覧

ユーザーがアーティストを選択した場合、そのアーティストに紐づくアルバムを一覧表示できなければならない。

- アルバム名を確認できる
- アルバムを選択できる
- 選択したアルバムに含まれる楽曲を表示できる

### FR-008 検索

ユーザーは楽曲をキーワードで検索できなければならない。

検索対象は、少なくともタイトル、アーティスト、アルバムとする。

検索結果がない場合は、その状態を明示する。

### FR-009 再生

ユーザーはライブラリまたは検索結果から楽曲を選択し、再生できなければならない。

最低限、以下の操作を提供する。

- 再生
- 一時停止

ファイルが移動・削除されていて再生できない場合は、原因が分かるエラーを表示する。

### FR-010 ライブラリの永続化

アプリを終了しても、登録フォルダ、ライブラリ情報、アプリ上で変更したメタデータ、ライブラリから削除した状態を保持しなければならない。

アプリ起動時には、保存された情報を読み込む。

### FR-011 メタデータ編集

ユーザーは、楽曲の以下のメタデータをアプリ上で変更できなければならない。

- タイトル
- アーティスト
- アルバム
- リリース情報

変更前に現在の値を確認でき、保存後は一覧や詳細表示に変更内容を反映する。

### FR-012 メタデータ一括編集

ユーザーは複数の楽曲を選択し、対象のメタデータをまとめて変更できなければならない。

- 複数の楽曲を選択・選択解除できる
- 選択中の楽曲数を確認できる
- 一括変更の対象項目と変更内容を確認できる
- 保存後、選択した全楽曲に変更内容を反映する
- 一括変更に失敗した場合は、変更結果とエラーを表示する

### FR-013 ライブラリからの削除

ユーザーは、選択した楽曲をライブラリから削除できなければならない。

- 削除前に確認を表示する
- 削除対象の楽曲を確認できる
- ライブラリからは削除する
- 元の音楽ファイルは削除しない
- 削除後、一覧、検索結果、アーティスト一覧、アルバム一覧に反映する

### FR-014 ファイルの安全性

アプリは、ユーザーが明示的に指示していない限り、音楽ファイルを以下のように扱ってはならない。

- 削除しない
- 移動しない
- 上書きしない
- 内容を変更しない

MVPのメタデータ編集はアプリ内のライブラリ情報を変更する機能とし、元の音楽ファイルへの書き戻しは行わない。

## 9. 非機能要件

### NFR-001 プラットフォーム対応

macOSとWindowsの両方で、MVPの主要機能を利用できること。

### NFR-002 応答性

- 大量ファイルのスキャン中も画面操作を受け付ける
- ファイルスキャンやメタデータ解析でUIを長時間ブロックしない
- 処理の進捗または処理中であることを表示する

### NFR-003 安全性

- ファイル操作の対象パスを検証する
- 予期しないファイルアクセスエラーを適切に処理する
- 秘密情報やユーザー固有のパスをログへ不用意に出力しない

### NFR-004 保守性

- UI、アプリケーションロジック、データアクセスを分離する
- ファイルシステムや再生機能を差し替え可能な構造にする
- 主要なロジックを単体テストで検証できるようにする

### NFR-005 テスト可能性

実装後、変更内容に応じて以下を実行する。

```bash
flutter analyze
flutter test
```

UIや主要なユーザーフローに変更がある場合は、Flutterの`integration_test`を実行する。

```bash
flutter test integration_test -d macos
flutter test integration_test -d windows
```

### メイン画面

- サイドバー
  - ライブラリ
  - アーティスト
  - アルバム
  - プレイリスト（MVP後）

画面構成やデザインは、実装時の検証結果に応じて変更できるものとする。

## 11. 受け入れ条件

### MVP受け入れ条件

- macOSでアプリを起動できる
- Windowsでアプリを起動できる
- ユーザーが音楽フォルダを登録・変更できる
- 登録フォルダ内の対応ファイルがライブラリに表示される
- アーティスト一覧を確認できる
- アーティストごとにアルバム一覧を確認できる
- タイトル、アーティスト、アルバム、リリース情報を確認・変更できる
- 複数楽曲のメタデータを一括変更できる
- 検索結果を正しく絞り込める
- 楽曲を再生・一時停止できる
- 楽曲をライブラリから削除できる
- ライブラリから削除しても元の音楽ファイルが残る
- アプリを再起動しても登録フォルダが保持される
- アプリを再起動してもメタデータ変更とライブラリからの削除が保持される
- 対象ファイルが存在しない場合にエラーを表示できる
- 実装後の静的解析とテストが成功する

## 12. テスト方針

- 検索、ソート、フィルタリング、メタデータ変換、アーティスト・アルバムのグルーピングは単体テストで検証する
- 個別画面やWidgetの状態はWidgetテストで検証する
- アプリ起動、フォルダ登録・変更、検索、再生、メタデータ編集、一括編集、ライブラリからの削除などの主要フローはIntegration Testで検証する
- テストでは実ユーザーの音楽フォルダを使用しない
- テスト用の音声ファイルと一時ディレクトリを用意する
- テスト未実行の場合、動作確認済みとして報告しない
