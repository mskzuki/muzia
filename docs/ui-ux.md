# Muzia UI / UX仕様書

## 1. 目的

MuziaのUI / UXは、ローカル音楽ライブラリを探し、整理し、再生する操作を少ない手順で行えることを目的とする。

macOSとWindowsのデスクトップアプリとして、マウス操作とキーボード操作の両方に対応する。

## 2. 対象範囲

### MVPに含める画面・操作

- アプリ起動
- ライブラリ画面
- 音楽フォルダの登録・変更
- 楽曲一覧
- アーティスト一覧
- アーティストごとのアルバム一覧
- 楽曲検索
- 楽曲の再生・一時停止
- 楽曲メタデータの編集
- 複数楽曲のメタデータ一括編集
- 楽曲のライブラリからの削除
- ローディング、空状態、エラー状態の表示

### MVP後に検討する画面・操作

- プレイリスト
- お気に入り、評価、タグ
- 再生履歴
- アルバムアートの表示・取得
- メディアキー対応
- メタデータの音楽ファイルへの書き戻し

## 3. UX原則

- 現在の状態を常に分かりやすく表示する
- ユーザーの音楽ファイルを安全に扱う
- 大量の楽曲を扱っても操作の流れを妨げない
- 重要な操作には結果を確認できるフィードバックを表示する
- 破壊的に見える操作には、実際の影響範囲を明示する
- マウスだけでなくキーボードでも主要操作を完了できるようにする
- macOS / Windowsの標準的な操作感を尊重する

## 4. 画面構成

### 4.1 基本レイアウト

```text
┌─────────────────────────────────────────────────────────┐
│ アプリタイトル / ウィンドウ操作                         │
├──────────────┬──────────────────────────────────────────┤
│              │ ツールバー                               │
│ サイドバー    ├──────────────────────────────────────────┤
│              │ メインコンテンツ                          │
│              │ 検索 / フィルター / 楽曲一覧              │
│              │                                          │
├──────────────┴──────────────────────────────────────────┤
│ プレイヤー: 曲情報 / 再生・一時停止                       │
└─────────────────────────────────────────────────────────┘
```

### 4.2 サイドバー

MVPでは以下のナビゲーションを表示する。

- ライブラリ
- アーティスト
- アルバム

MVP後の機能は、未実装の状態でナビゲーションに表示しない。表示する場合は、利用できない理由または予定を明示する。

### 4.3 ツールバー

画面上部に、現在の画面に応じた操作を表示する。

共通要素:

- 画面タイトル
- 検索フィールド
- フォルダ登録・変更操作
- 再スキャン操作
- 必要に応じた選択操作

### 4.4 メインコンテンツ

ライブラリ、アーティスト、アルバムなど、サイドバーで選択した内容を表示する。

コンテンツには以下の状態を持たせる。

- 初期状態
- 読み込み中
- データあり
- データなし
- 検索結果なし
- エラー

### 4.5 プレイヤー

画面下部に固定表示する。

MVPでは以下を提供する。

- 現在選択中の楽曲情報
- 再生ボタン
- 一時停止ボタン
- 再生中・停止中の状態
- 再生エラーの表示

前後の曲への移動、再生位置、音量変更などはMVP後に検討する。

## 5. 画面仕様

### 5.1 ライブラリ画面

表示内容:

- 楽曲一覧
- タイトル
- アーティスト
- アルバム
- リリース情報
- 選択状態

操作:

- 楽曲を選択する
- 楽曲を再生する
- 楽曲を一時停止する
- 楽曲を複数選択する
- メタデータ編集を開始する
- ライブラリから削除する

### 5.2 アーティスト画面

表示内容:

- アーティスト名の一覧
- 各アーティストに属する楽曲数（表示可能な場合）

操作:

- アーティストを選択する
- 選択したアーティストのアルバム一覧を表示する

### 5.3 アルバム画面

表示内容:

- 選択したアーティストに紐づくアルバム一覧
- アルバム名
- 各アルバムに属する楽曲数（表示可能な場合）

操作:

- アルバムを選択する
- 選択したアルバムの楽曲一覧を表示する

### 5.4 フォルダ登録・変更

操作フロー:

```text
フォルダ登録・変更を選択
  ↓
OSのフォルダ選択ダイアログ
  ↓
対象フォルダを選択
  ↓
確認または処理開始
  ↓
スキャン中の状態を表示
  ↓
ライブラリを更新
```

要件:

- フォルダ選択はOS標準のダイアログを使用する
- キャンセルした場合、現在の登録内容を変更しない
- フォルダ変更時は変更前と変更後のフォルダを明示する
- スキャン中は処理中であることを表示する
- スキャン中も、可能な範囲で画面操作を継続できるようにする
- フォルダが存在しない場合は原因と対処方法を表示する

### 5.5 検索

検索対象:

- タイトル
- アーティスト
- アルバム

要件:

- 入力中に検索結果を更新する
- 大文字・小文字の違いで検索結果が不自然に変わらないようにする
- 検索文字列を消去できる
- 検索結果がない場合は「該当する楽曲がありません」などの状態を表示する
- 検索中に発生したエラーを表示する

検索仕様の詳細（部分一致、単語一致、全角・半角の扱いなど）は実装前に確定する。

### 5.6 メタデータ編集

編集対象:

- タイトル
- アーティスト
- アルバム
- リリース情報

要件:

- 編集開始時に現在の値を表示する
- 保存とキャンセルを明確に分ける
- キャンセル時は変更を破棄する
- 保存中は処理中の状態を表示する
- 保存成功後は一覧、検索結果、アーティスト一覧、アルバム一覧へ反映する
- 保存失敗時は入力内容を失わないようにする
- MVPでは元の音楽ファイルへ書き戻さないことを表示または説明する

### 5.7 メタデータ一括編集

要件:

- 楽曲一覧から複数の楽曲を選択できる
- 選択中の楽曲数を表示する
- 選択をすべて解除できる
- 一括編集の対象項目を明示する
- 保存前に対象楽曲数と変更内容を確認できる
- 保存成功後に全対象楽曲へ反映する
- 保存失敗時に成功・失敗の状態を明示する

一括編集時に空欄を指定した場合の動作（値を空にするか、変更しないか）は実装前に確定する。

### 5.8 ライブラリからの削除

操作フロー:

```text
楽曲を選択
  ↓
ライブラリから削除を選択
  ↓
確認ダイアログ
  ↓
ライブラリから非表示
```

確認ダイアログには、以下を明示する。

- ライブラリからのみ削除されること
- 元の音楽ファイルは削除されないこと
- 対象楽曲数

削除後は、楽曲一覧、検索結果、アーティスト一覧、アルバム一覧から対象を除外する。

## 6. 状態表示

### ローディング

表示内容:

- 実行中の処理
- 必要に応じた進捗
- 処理を中断できる場合は中断操作

例:

- 「ライブラリを読み込んでいます」
- 「音楽ファイルをスキャンしています」
- 「メタデータを解析しています」

### 空状態

空状態には、状態の説明と次の操作を表示する。

例:

- フォルダ未登録: 「音楽フォルダを登録してください」＋登録ボタン
- 楽曲なし: 「対応する音楽ファイルがありません」
- 検索結果なし: 「条件に一致する楽曲がありません」
- アーティストなし: 「アーティストがありません」

### エラー

エラーには以下を含める。

- 何が失敗したか
- ユーザーが取れる対処
- 再試行できる場合の操作

内部例外、SQL、スタックトレースなどの実装詳細は通常のUIに表示しない。

## 7. デスクトップ操作

- ウィンドウのリサイズに対応する
- 狭いウィンドウでも主要操作が隠れないようにする
- 一覧はキーボードでフォーカス移動できるようにする
- EnterまたはSpaceで選択項目の主要操作を実行できるようにする
- Escapeでダイアログや編集状態をキャンセルできるようにする
- Cmdキー（macOS）とCtrlキー（Windows）のショートカット差異を考慮する
- 右クリックメニューは、主要操作の代替としてのみ使用する
- OS標準のフォルダ選択ダイアログを利用する

キーボードショートカットの詳細は、MVPの主要操作を確認した後に確定する。

## 8. アクセシビリティ

- ボタンや入力欄に意味のあるラベルを付ける
- 色だけで状態を伝えない
- 選択状態を視覚以外でも確認できるようにする
- フォーカス位置を視認できるようにする
- 文字が長い楽曲名でも、切り捨てやツールチップなどで確認できるようにする
- エラーや成功状態を、画面上で読み取れるテキストとして表示する

## 9. ビジュアル方針

以下は未決定であり、実装前またはプロトタイプ作成時に確定する。

- カラーテーマ
- フォント
- アイコンセット
- 角丸や余白の基準
- ライト・ダークテーマの対応
- macOS寄りのUIとWindows寄りのUIの使い分け

未決定のビジュアル要素を導入する場合は、既存画面との一貫性を優先する。

## 10. 受け入れ条件

- アプリ起動時に初期状態、読み込み中、成功、エラーを識別できる
- フォルダを登録・変更できる
- 楽曲、アーティスト、アルバムを切り替えて表示できる
- 検索結果と検索結果なしの状態を確認できる
- 楽曲を選択して再生・一時停止できる
- メタデータを編集して一覧へ反映できる
- 複数楽曲を選択してメタデータを一括編集できる
- ライブラリから削除しても元ファイルが削除されない
- macOS / Windowsで主要操作をキーボードから実行できる
- 画面をリサイズしても主要操作が利用できる
